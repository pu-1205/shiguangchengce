# ***\*1. 产品概述\****

## ***\*1.1 产品定位\****

CardFlow 是一款基于抖音收藏视频的知识管理与行动落地工具。它将用户被动收藏的视频内容，通过 AI 自动摘要、分类、卡片化，转化为可消化、可执行的知识卡片，并通过实践记录和成就体系激励用户将所学真正付诸行动。

 

## ***\*1.2 核心痛点\****

| ***\*用户痛点分析\****                                       |
| ------------------------------------------------------------ |
| ① 收藏坟墓问题：用户收藏视频后，二次回看率极低（<5%），大量内容沉淀在收藏夹从未被再次消费② 重复查看成本高：二次回看需要从头完整播放视频，时间成本高，意愿低③ 知识停留在看的层面：视频内容仅供娱乐消费，缺乏转化为实际行动的路径和激励机制④ 内容碎片化无法管理：不同类型视频混杂在收藏夹，无有效分类和检索手段 |

 

## ***\*1.3 产品价值主张\****

| ***\*价值维度\**** | ***\*具体描述\****                               |
| ------------------ | ------------------------------------------------ |
| 效率提升           | AI自动摘要，将30分钟视频压缩为2分钟可读卡片      |
| 知识沉淀           | 卡片化存档，知识可检索、可回顾、可分类           |
| 行动落地           | 一键生成实践步骤卡片，降低从「看」到「做」的门槛 |
| 正向激励           | 行动记录 + 勋章体系，形成正向行为激励闭环        |
| 个性化管理         | 用户可自定义卡片内容，添加个人笔记和感想         |

| ***\*维度\**** | ***\*描述\****                                      |

## ***\*2.2 用户旅程地图\****

| ***\*用户核心旅程\****                                       |
| ------------------------------------------------------------ |
| Step 1：在抖音刷到感兴趣视频 → 点击收藏Step 2：进入 CardFlow 个人空间 → 看到分类书架Step 3：进入感兴趣分类 → 浏览知识卡片列表Step 4：点击封面卡片 → 快速了解视频核心内容Step 5A（纯学习路径）：点击内容卡片 → 查看详细知识闪卡/步骤卡Step 5B（实践路径）：点击「实践」按钮 → 生成实践步骤卡片并记录行动Step 6：积累行动记录 → 解锁勋章 → 主页展示成就 |

 



# ***\*3. 功能架构\****

## ***\*3.1 整体功能模块\****

| ***\*模块\**** | ***\*核心功能\****                                    |
| -------------- | ----------------------------------------------------- |
| 个人空间主页   | 收藏书架入口 / 今日行动记录 / 勋章展示 / 情绪状态选择 |
| 分类书架       | 按话题自动分类（健身/理财/技能等）/ 分类详情浏览      |
| 卡片系统       | 封面卡片 / 内容卡片（知识类）/ 内容卡片（实操类）     |
| 实践系统       | 实践步骤生成 / 步骤自定义编辑 / 行动记录              |
| 成就系统       | 行动积累计数 / 勋章解锁 / 成就展示                    |
| AI引擎（后端） | 视频摘要生成 / 内容分类 / 关键观点提炼 / 步骤拆解     |

 

## ***\*3.2 卡片系统详细设计\****

### ***\*3.2.1 封面卡片\****

| ***\*封面卡片组成要素\****                                   |
| ------------------------------------------------------------ |
| ① 视频缩略图（顶部）② 视频标题（大字显示）③ 核心观点摘要（3-5条，AI自动提炼）④ 来源信息（博主名称、发布时间）⑤ 「查看内容」按钮 → 进入详情卡片⑥ 「开始实践」按钮 → 生成实践步骤卡片 |

 

### ***\*3.2.2 内容卡片 — 知识类\****

| ***\*知识类卡片（适用于：阅读/金融/科普/访谈等）\****        |
| ------------------------------------------------------------ |
| 展示形式：知识闪卡（Flash Card）样式• 正面：知识点标题 / 核心问题• 背面：AI生成的详细解释 / 原视频对应时间戳• 每条知识点独立一张卡片，支持左右滑动浏览• 自定义区域：用户可修改AI生成内容 / 添加个人笔记和感想• 记忆辅助：支持标记「已掌握」/ 「需复习」状态 |

 

### ***\*3.2.3 内容卡片 — 实操类\****

| ***\*实操类卡片（适用于：健身/烹饪/电脑操作/技能教程等）\**** |
| ------------------------------------------------------------ |
| 展示形式：步骤化卡片列表• 步骤一二三四…（AI自动拆解，每步配图或时间戳）• 每步显示：步骤名称 + 具体说明 + 注意事项• 自定义区域：用户可修改步骤描述 / 添加个人记录• 实践勾选框：每步完成后可勾选，记录进度 |

 



# ***\*4. 数据流与技术架构\****

## ***\*4.1 核心数据流\****

| ***\*数据处理流程\****                                       |
| ------------------------------------------------------------ |
| ① 数据获取层  用户授权 → 抖音开放平台 API 拉取收藏视频列表（视频ID、标题、URL、封面图） ② AI处理层  视频元数据 → LLM分析（标题+描述+字幕） → 输出：摘要 / 关键观点 / 分类标签 / 卡片类型判断 ③ 卡片生成层  AI输出 → 结构化JSON → 前端渲染为对应卡片类型 ④ 用户交互层  用户操作（点赞/编辑/实践/勾选） → 本地/云端存储 → 行动记录 + 成就更新 |

 

## ***\*4.2 API接口设计（后端实现清单）\****

| ***\*接口\****              | ***\*说明\****                                 |
| --------------------------- | ---------------------------------------------- |
| GET /api/favorites          | 拉取用户抖音收藏视频列表（需用户OAuth授权）    |
| POST /api/cards/generate    | 传入视频ID，触发AI生成卡片数据，返回结构化JSON |
| GET /api/cards/{videoId}    | 获取指定视频的卡片数据（含封面/知识点/步骤）   |
| GET /api/categories         | 获取用户所有卡片的分类列表（书架数据）         |
| POST /api/practice/start    | 用户点击实践，创建一条实践记录                 |
| PUT /api/practice/{id}/step | 更新某个实践步骤的完成状态或内容               |
| GET /api/activity/log       | 获取用户的今日行动记录列表                     |
| GET /api/achievements       | 获取用户的勋章/成就列表                        |
| POST /api/cards/{id}/note   | 用户在卡片上保存自定义笔记                     |

 



# ***\*5. AI 卡片生成规范（Prompt 设计）\****

## ***\*5.1 视频分类判断\****

| ***\*分类判断 Prompt 模板\****                               |
| ------------------------------------------------------------ |
| System: 你是一个内容分类专家，根据视频标题和描述，判断该视频属于哪个主题类别，并判断内容类型。 Input: { "title": "视频标题", "description": "视频描述", "tags": ["标签1","标签2"] } Output JSON格式:{ "category": "健身",      // 主分类：健身/理财/技能/科普/生活/烹饪/其他 "card_type": "practice",   // practice=实操类 \| knowledge=知识类 "confidence": 0.92      // 置信度} |

 

## ***\*5.2 封面卡片生成\****

| ***\*封面卡片 Prompt 模板\****                               |
| ------------------------------------------------------------ |
| System: 你是一个视频摘要专家。根据视频信息，生成简洁的封面卡片内容。要求语言精炼、重点突出。 Input: { "title": "...", "description": "...", "subtitle": "...", "duration": 300 } Output JSON格式:{ "cover_title": "10分钟学会腹肌训练全套动作", "key_points": [  "无需器械，适合家庭训练",  "核心3个动作：卷腹/平板支撑/抬腿",  "每周3次，坚持4周见效" ], "duration_read": "2分钟",  // 预估阅读卡片时间 "difficulty": "入门"     // 入门/进阶/专家} |

 

## ***\*5.3 实操步骤卡片生成\****

| ***\*实操卡片 Prompt 模板\****                               |
| ------------------------------------------------------------ |
| System: 你是一个教程结构化专家。将视频教程内容拆解为清晰的步骤，每步要具体可操作。 Output JSON格式:{ "steps": [  {   "step_no": 1,   "title": "热身5分钟",   "description": "做开合跳50次，放松关节，防止受伤",   "duration": "5分钟",   "tips": "动作要到位，不要急于完成次数"  } ], "total_time": "30分钟", "equipment": ["瑜伽垫"]} |

 

## ***\*5.4 知识闪卡生成\****

| ***\*知识闪卡 Prompt 模板\****                               |

# ***\*7. 黑客松实现策略\****

## ***\*7.1 MVP优先级划分\****

| ***\*MVP核心功能（必须跑通）\****                            |
| ------------------------------------------------------------ |
| ✅ 1. 抖音收藏视频数据模拟（Mock数据即可，不依赖真实API）✅ 2. AI调用生成封面卡片（标题 + 关键观点）✅ 3. 封面卡片页面渲染和展示✅ 4. 点击实践 → 生成实操步骤卡片（实操类视频）✅ 5. 点击内容 → 生成知识闪卡（知识类视频）✅ 6. 行动记录写入主页（今日做了什么） |

 

| ***\*Nice-to-have（时间允许再做）\****                       |
| ------------------------------------------------------------ |
| ⭕ 分类书架自动归类⭕ 勋章解锁逻辑⭕ 用户自定义编辑卡片内容⭕ 情绪状态选择功能 |

 

## ***\*7.2 后端实现路径（Trae执行清单）\****

### ***\*Task 1：数据层搭建\****

• 创建Mock数据集：模拟10条抖音收藏视频（含标题/描述/封面/时长/标签）

• 数据结构：video_id, title, description, cover_url, duration, tags, category

• 存储方案：JSON文件 或 SQLite数据库（黑客松阶段用JSON即可）

 

### ***\*Task 2：AI接口封装\****

• 封装 /api/cards/generate 接口

• 输入：video_id，读取对应Mock视频数据

• 调用LLM：发送视频信息 → 获取JSON结构化输出

• 支持两种输出模式：practice（实操步骤）和 knowledge（知识闪卡）

• 缓存机制：同一视频第二次请求直接返回缓存，不重复调用LLM

 

### ***\*Task 3：行动记录接口\****

• POST /api/practice/start：传入video_id，创建实践记录

• PUT /api/practice/{id}/step：更新步骤完成状态

• GET /api/activity/log：返回当天所有行动记录

 

### ***\*Task 4：分类接口\****

• GET /api/categories：遍历所有视频数据，返回分类聚合结果

• GET /api/categories/{name}/cards：返回该分类下所有已生成的卡片

 



# ***\*8. 核心数据结构定义\****

## ***\*8.1 视频数据（Mock）\****

| ***\*Video 数据模型\****                                     |
| ------------------------------------------------------------ |
| interface Video { video_id: string;      // 视频唯一ID title: string;       // 视频标题 description: string;    // 视频描述/简介 cover_url: string;     // 封面图URL duration: number;      // 时长（秒） author: string;       // 博主名称 tags: string[];       // 标签列表 collected_at: string;    // 收藏时间（ISO 8601） category?: string;     // AI分类结果（可选，生成后填入） card_type?: 'practice' \| 'knowledge'; // AI判断的卡片类型} |

 

## ***\*8.2 卡片数据\****

| ***\*Card 数据模型\****                                      |
| ------------------------------------------------------------ |
| interface Card { card_id: string; video_id: string; cover: {  cover_title: string;  key_points: string[];  duration_read: string;  difficulty: string; }; content: PracticeContent \| KnowledgeContent; user_notes: string;     // 用户自定义笔记 created_at: string;} interface PracticeContent { type: 'practice'; steps: { step_no: number; title: string; description: string; tips: string; completed: boolean; }[]; total_time: string;} interface KnowledgeContent { type: 'knowledge'; flash_cards: { id: number; question: string; answer: string; mastered: boolean; }[];} |

 

## ***\*8.3 行动记录\****

| ***\*ActionLog 数据模型\****                                 |
| ------------------------------------------------------------ |
| interface ActionLog { log_id: string; video_id: string; card_title: string;     // 显示在「我做了什么」列表中 action_type: string;    // '完成实践' \| '学习闪卡' \| '浏览内容' duration_min: number;    // 花费时间（分钟） completed_steps: number;  // 完成步骤数（实操类） timestamp: string;     // 行动时间} |

 



# ***\*9. 非功能性需求\****

| ***\*维度\**** | ***\*要求\****                                       |
| -------------- | ---------------------------------------------------- |
| 响应时间       | AI卡片生成 < 5秒（使用流式输出提升体验）             |
| 缓存策略       | 同一视频的卡片数据缓存7天，避免重复LLM调用           |
| 容错处理       | AI生成失败时显示友好提示，支持手动重试               |
| 离线支持       | 已生成的卡片数据本地缓存，支持离线浏览               |
| 数据安全       | 用户行动记录仅本地存储，不上传至服务器（黑客松阶段） |
